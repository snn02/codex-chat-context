# Панель контекста Codex в оформлении по образцу Claude

Статус: проект для согласования перед реализацией.

## Задача и согласованные предпочтения

Пользователь хочет панель рядом с текущим чатом, максимально близкую по оформлению и возможностям к присланному примеру Claude. Оценочные значения приемлемы; высокая точность не является условием первой версии.

Панель должна объяснять заполненность окна и предполагаемый вклад разных категорий, раскрывать известные инструменты, файлы инструкций и навыки. Она использует существующий локальный плагин `context-panel-probe@context-panel-probe-local`. Привязка к настоящему ID чата, собственный HTML справа и отдельные экземпляры для разных чатов уже проверены.

## Внешний вид

- Образец: `C:/Users/SAWA/AppData/Local/Temp/codex-clipboard-313027a1-6932-4944-bef5-fadc759232d7.png`.
- Одна светлая карточка с тонкой серой рамкой, скруглениями, спокойной типографикой и без технического JSON на основном экране.
- Заголовок «Контекст», ниже крупное «≈54% занято» слева и «≈140,9k / 258,4k» справа. Эти числа — пример по наблюдению, а не константы интерфейса.
- Составная тонкая горизонтальная полоса. Категории: синий для сообщений, оранжевый для встроенных инструментов, зелёный для файлов инструкций, серые оттенки для остальных групп, светло-серый для свободного места.
- У строк цветной маркер, название, количество токенов и процент от лимита окна. Числа выровнены вправо, разряды не скачут при обновлении.
- Раскрывающиеся списки с количеством известных элементов: MCP, встроенные инструменты, файлы инструкций, навыки. Длинные имена сокращаются; полный путь или имя доступны в подсказке.
- Списки имеют ограничение высоты и внутреннюю прокрутку. Основная карточка адаптируется к ширине панели; горизонтальной прокрутки нет.
- Компактная строка «Обновлено …» и кнопка обновления. Источник и способ оценки доступны в подсказках. ID чата и диагностика — в свёрнутом блоке.
- Русские подписи, формат чисел k/M, поддержка темы хоста и доступное управление раскрытием с клавиатуры.

## Данные и подтверждённые возможности

В журнале текущего чата обнаружены:

- `event_msg/token_count`: `last_token_usage`, накопительный `total_token_usage`, `model_context_window`.
- На момент проверки `2026-10-19T20:09:52.157Z`: input 140598, output 267, total 140865, окно 258400. Накопительный расход больше 4 млн и не является текущей заполненностью окна.
- `turn_context`: модель и уровень рассуждений.
- `world_state`: сведения об инструкциях, каталоге навыков и кратких описаниях доступных пространств инструментов. Это не обязательно полные схемы всех инструментов.
- Сообщения и вызовы инструментов в структурированных записях журнала.

Официальный протокол App Server также содержит чтение метаданных/истории, события использования токенов и сжатия. Однако отдельный запуск App Server в текущей ограниченной среде завершился ошибкой инициализации SQLite в каталоге `.codex`. Для первой версии он не нужен: чтение существующего журнала уже работает.

Источники для проектирования: локальная схема CLI `0.162.0-alpha.17.2`; https://learn.chatgpt.com/docs/app-server ; https://developers.openai.com/plugins/build/chatgpt-ui .

## Варианты источника данных

1. **Рекомендуется для первой версии: локальный журнал, только чтение.** Уже содержит реальные счётчики; не требует подключения к активному App Server и запуска модельных запросов. Недостаток: внутренний формат может меняться, нужны проверки формата и состояния «данные недоступны».
2. **Подключение к App Server.** Более явный протокол, потенциально живые события. Нужна отдельная проверка доступа к активному чату и его обновлениям. Наличие поля в схеме не доказывает возможность подписки из нашего процесса.

Первая версия использует вариант 1; сборщик отделён от UI, чтобы позже можно было добавить вариант 2.

## Категории и оценка

| Категория | Что показываем |
|---|---|
| Сообщения | Оценка доступных сообщений и результатов инструментов в восстановимом текущем участке истории. Выделенные в другие группы фрагменты повторно сюда не входят. |
| Встроенные инструменты | Известные описания/схемы, если они присутствуют в источнике. При неполных данных — оценка только доступной части или «нет данных». |
| Файлы инструкций | Обнаруженные источники AGENTS.md и аналогичных пользовательских инструкций. Различаем «подтверждён в снимке», «прочитан» и «только найден». Последнее не входит автоматически в сумму. |
| MCP-инструменты | Известные загруженные описания. Если известны только серверы/пространства имён, показываем именно их, без выдуманного количества инструментов. |
| Навыки | Каталог навыков и подтверждённо загруженные тексты. Каталог не равен полной загрузке всех SKILL.md. |
| Прочий системный контекст | Неатрибутированный остаток между общей базой и оценкой известных частей. Не представляем остаток как точный размер системного промпта. Скрытые служебные инструкции и внутренние рассуждения текстом не показываем. |
| После последнего измерения | Оценка новых записей, ещё не покрытых последним счётчиком. Не прибавляем к ней уже учтённые записи. |
| Резерв до сжатия | Только если найден применимый порог. Если нет — необязательный пользовательский резерв, по умолчанию выключен, с явной пометкой «настройка панели». Не копируем процент Claude. |
| Свободное место | Остаток после оценки занятого места и отдельно известного/настроенного резерва. |
| Отложенные MCP / встроенные инструменты | Отдельные приглушённые списки. В заполненность автоматически не входят; размер краткого каталога не выдаётся за размер полных схем. Неизвестное показываем прочерком. |

Правила подсчёта:

- База общего показателя — последнее `last_token_usage.total_tokens` (или input + output, если total отсутствует), а не накопительный расход. Это ориентир размера последнего запроса с ответом, не обещание точного текущего prompt.
- Размер окна берём из `model_context_window` этого чата. Если он неизвестен, процент и свободное место не вычисляем; не подставляем 1M из образца.
- Оценка текстовых частей использует локальную детерминированную эвристику с учётом кириллицы, латиницы и кода. Можно позже заменить её токенизатором; сетевой запрос для подсчёта не нужен.
- Один фрагмент имеет только одну категорию. Если нельзя надёжно выделить загруженный файл из результата инструмента, оставляем его в сообщениях, а файл показываем как справочный элемент без повторного начисления токенов.
- Если сумма оценок частей превышает базу, пропорционально нормируем части до базы и помечаем разбивку как оценочную. Если меньше — разницу показывает «Прочий системный контекст». В подсказке объясняем нормировку.
- Сжатие/уменьшение счётчика сбрасывает оценку прироста. Если текущий участок истории после сжатия восстановить нельзя, общий счётчик остаётся видимым, а историческая разбивка отмечается неполной. Старую историю не выдаём за активный контекст.
- Изображения, скрытое содержимое, неизвестные схемы и служебный формат могут входить в остаток. Недоступное значение — не ноль.
- Все проценты в таблице относятся к одному лимиту окна. Отложенные элементы исключены из составной полосы. Переполнение показывается явно, а не отрицательным свободным местом.

## Устройство реализации

- Сохраняем `server.cjs` и `panel.html` существующего плагина, добавляем отдельный модуль чтения/оценки контекста и проверки на обезличенных фикстурах.
- Инструмент получения снимка работает без передаваемого UI `threadId`. Берёт привязку из служебных метаданных запроса, проверяет согласованность полей; при отсутствии/конфликте отказывает с понятным состоянием UI.
- Индекс файлов строится по UUID чата в локальном каталоге sessions. Проверяется идентификатор session_meta. Не используем «самый свежий чат» и не подменяем ID переменной окружения процесса.
- Чтение журналов и файлов только локальное. Не меняем историю, не запускаем ход модели, не отправляем данные во внешние сервисы. В ответ UI передаются агрегаты, имена и источники, а не вся переписка.
- Кеш и состояние обновления раздельны по ID чата. Чтение инкрементальное, с обработкой неполной последней JSONL-строки, замены/усечения файла и ограничением объёма чтения за один проход.
- UI обновляет снимок раз в 5 секунд, пока видим, и при возвращении к нему. Таймеры не перекрываются; устаревший ответ не заменяет более новый снимок. Для скрытой панели опрос приостанавливается.
- Данные остаются видны при кратком сбое, но отмечаются как устаревшие. Состояния: загрузка, нет привязки, нет журнала, нет счётчика, неполная оценка, ошибка чтения.
- Сохраняем идентичность установленного плагина; не создаём дубликат. Название интерфейса меняем на «Контекст чата». Перезагрузка выполняется поддерживаемым локальным способом после проверки исходников.

## Проверка результата

1. Числа общего показателя сверяются с реальным token_count; накопительные миллионы не попадают в заполненность.
2. Фикстуры проверяют кириллицу/код, отсутствие счётчика, неполную JSONL-строку, сжатие, переполнение, нормировку и отсутствие двойного подсчёта.
3. Снимки двух чатов не смешиваются при чередовании запросов; отсутствующий/конфликтующий ID не использует чужой кеш.
4. UI близок к образцу: карточка, полоса, выровненные числовые колонки, раскрытие списков, прокрутка, адаптация к узкой панели.
5. В Codex проверяются открытие, обновление, правильный ID и переход A → B → A. Отдельно проверяется остановка опроса скрытой панели.
6. Не создаются новые чаты, экземпляры плагина или запросы к модели ради подсчёта.

## Границы первой версии

Это оценочная панель по доступным локальным данным, а не точная копия внутренней статистики Claude или инспектор полного запроса к модели. Список сохраняет максимум полезных аналогов образца, но недоступные данные не заполняются вымышленными значениями. Оценка стоимости, кнопка принудительного сжатия и редактирование памяти не входят в первую версию.
